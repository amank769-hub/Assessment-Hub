The shape of it

Four planes, one direction of travel

Everything in the platform sits in one of four planes, and dependencies only ever point downward. A screen can read the record; the record has never heard of a screen.

That constraint is what makes the interesting part possible. Because the engine knows nothing about the surfaces, adding a fifth interview level is a data change, not a new screen.

Flow 02 — the generative core

One declaration, N levels

This is the single architectural decision the whole product turns on. The requisition declares its workflow as data. Interviews, scorecards and the consolidated rollup are all generated from that declaration — nothing downstream is written by hand.

The assessment sheet we started from has five fixed tabs: TA Partner, Business 1, Business 2, HR Partner, Segment Head. A sixth round meant a new tab and a new set of formulas. Here the same code path produces four levels for the Bangalore sales role and five for the Singapore finance role, because those requisitions declared different arrays.

What this buys the team

A hiring manager who wants a fifth round adds a stage from the workflow tab. The matching scorecard appears for every candidate already in process, the comparison matrix grows a column, and the rollup recomputes. Nobody opens an editor.

Flow 03 — the handoff

Where the machine stops

Read this one as two lanes. Work moves down the top lane until it reaches something only a person can do, crosses to the bottom lane, and comes back. The crossings are the product.

The guard, in the code

Gate 2 is not a convention anyone can forget. SIGN_OFF refuses and explains itself unless all three conditions hold:

  • unrated === 0Every competency row carries a rating on the six-point scale. No decimals, as the sheet specifies.
  • culturalFitment != nullA value from the three-point fitment scale has been chosen.
  • finalDecision != nullOne of the three IAS outcomes is recorded: suitable, on hold, or not suitable.

What the machine contributes

A suggested rating, the evidence it came from, and a confidence figure. Visible, labelled, and worth nothing until someone agrees with it.

What counts

Only rows a person has confirmed enter weightedAverage. An untouched AI draft scores zero, not 4.7.

The record

Six entities carry the whole product. The cardinalities are where the dynamism lives — every 1:N on this diagram is a place the requisition gets to decide N.

How state actually moves

One reducer holds everything. A screen dispatches, the reducer returns new entities plus an audit entry, and derived selectors recompute from there. There is no second source of truth to fall out of sync.

ActionWhat it changesWrites audit
SCREEN_DECISIONCandidate status and stage; closes the screening taskYes, with the AI suggestion alongside

Reference

Where this plugs into what you already run

Nexora is the interview and decision layer, not a system of record. The planes in figure 01 are drawn the way they are so an existing ATS can own the record without any of this changing.

Live today

Invites and reminders by email. Branded PDF export of comparisons and scorecards. Multi-country scheduling in each interview's own timezone.

Designed for, not wired

Calendar sync for panel availability. Native video platform meetings and recording ingestion. ATS requisition and candidate sync.

Deliberately absent

Auto-rejection. Ranking that picks rather than orders. Any path from a model output to a candidate-facing outcome without a signature.
